# Git Delete Branch

Deleting a Git branch means removing the **branch reference** that points to a commit. The commits themselves are not necessarily deleted; removing the branch simply means that the line of development is no longer accessible through that branch name.

Branches can be deleted **locally**, **remotely**, or both.

## When to Delete a Branch

Git repositories commonly have multiple branches for developing features, fixing bugs, or experimenting with changes while keeping the main codebase isolated.

For example:

```text
main
 ├── feature/login
 ├── feature/payment
 └── fix/authentication
```

Once a feature or fix has been completed and merged, its branch may no longer be needed and can be deleted.

> [!NOTE]  
> Deleting a branch is generally safe after its changes have been merged. The branch reference is removed, but the commits may still be reachable through other references.

---

## Delete a Branch Locally

### Step 1: Switch to Another Branch

You cannot delete the branch that you are currently on.

For example, if you want to delete `fix/authentication`, first switch to `main`:

```bash
git switch main
```

The older equivalent is:

```bash
git checkout main
```

### Step 2: Delete the Branch

Use:

```bash
git branch -d <branch-name>
```

Example:

```bash
git branch -d fix/authentication
```

The `-d` option performs a **safe deletion**. Git will normally refuse to delete the branch if it contains commits that have not been merged into another branch.

> [!TIP]  
> The important condition is whether the branch's commits have been merged into another reachable branch, not whether the branch was merely pushed to a remote.

---

## Force Delete a Local Branch

If you want to delete a branch even though Git considers it unmerged, use:

```bash
git branch -D <branch-name>
```

Example:

```bash
git branch -D fix/authentication
```

Here:

- `-d` → safe deletion
- `-D` → force deletion

> [!WARNING]  
> Use `-D` carefully. If the branch contains commits that are not reachable elsewhere, deleting the branch can make those commits harder to recover.

---

## Delete a Branch Remotely

Deleting a local branch does **not** delete the corresponding branch on the remote repository.

To delete a remote branch, use:

```bash
git push <remote> --delete <branch-name>
```

For example:

```bash
git push origin --delete fix/authentication
```

Here:

- `origin` → the name of the remote repository
- `fix/authentication` → the remote branch being deleted

---

## Alternative Syntax for Deleting a Remote Branch

Git also supports an older, shorter syntax:

```bash
git push <remote> :<branch-name>
```

Example:

```bash
git push origin :fix/authentication
```

This has the same purpose as:

```bash
git push origin --delete fix/authentication
```

The `--delete` form is generally easier to understand and is preferred for readability.

---

## Synchronize Local Remote-Tracking Branches

Sometimes a remote branch has already been deleted by someone else, but your local repository still shows the corresponding **remote-tracking branch**.

You can synchronize your remote-tracking references with:

```bash
git fetch -p
```

The `-p` option means **prune**.

It removes local remote-tracking references for branches that no longer exist on the remote.

For example:

```text
Remote repository:

origin/main
origin/feature/login
```

If `origin/feature/login` is deleted from the remote, your local repository may temporarily still show:

```text
origin/main
origin/feature/login
```

Running:

```bash
git fetch -p
```

updates the remote-tracking references so the stale `origin/feature/login` reference is removed.

> [!IMPORTANT]  
> `git fetch -p` does not delete local branches. It prunes **stale remote-tracking references**.

---

## Local vs. Remote Branch Deletion

|Task|Command|
|---|---|
|Delete local branch safely|`git branch -d <branch>`|
|Force-delete local branch|`git branch -D <branch>`|
|Delete remote branch|`git push origin --delete <branch>`|
|Alternative remote deletion|`git push origin :<branch>`|
|Remove stale remote-tracking references|`git fetch -p`|
|List local branches|`git branch`|
|List remote-tracking branches|`git branch -r`|
|List all branches|`git branch -a`|

---

## Typical Workflow

Suppose you have finished working on:

```text
fix/authentication
```

and the changes have already been merged into `main`.

### Delete the local branch

```bash
git switch main
git branch -d fix/authentication
```

### Delete the remote branch

```bash
git push origin --delete fix/authentication
```

### Verify the branches

```bash
git branch
```

To check remote-tracking branches:

```bash
git branch -r
```

## Quick Reference

```bash
# Switch to another branch
git switch main

# Delete a local branch safely
git branch -d fix/authentication

# Force-delete a local branch
git branch -D fix/authentication

# Delete a remote branch
git push origin --delete fix/authentication

# Alternative remote deletion syntax
git push origin :fix/authentication

# Prune stale remote-tracking references
git fetch -p
```

## Key Takeaways

- A Git branch is a **reference/pointer to a commit**.
- Deleting a branch removes that reference; it does not necessarily immediately delete the commits.
- You cannot normally delete the branch you are currently on.
- `git branch -d` safely deletes a local branch when Git considers it merged.
- `git branch -D` force-deletes a local branch.
- Deleting a local branch does **not** delete its remote counterpart.
- `git push origin --delete <branch>` deletes a remote branch.
- `git fetch -p` removes stale **remote-tracking references** for branches that no longer exist on the remote.
