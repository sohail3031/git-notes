# Introduction to GitHub

## What Is GitHub?

[GitHub](https://github.com/) is a web-based platform built around [Git](https://git-scm.com/), the open-source distributed version control system.

GitHub provides a web interface for working with Git repositories and adds collaboration features such as:

- Pull requests
- Issues
- Code review
- Project management
- Repository hosting
- Team and organization management
- Notifications
- Wikis and documentation
- Repository settings

Git itself handles version control, while GitHub provides a platform for hosting repositories and collaborating with other people.

> [!NOTE]  
> GitHub is **not Git**. Git is the version control tool; GitHub is a platform that hosts Git repositories and provides collaboration features around them.

## GitHub Interface

The GitHub interface is the web-based dashboard used to navigate and manage repositories, pull requests, issues, account settings, and other GitHub features.

Common areas include:

- **Repository view** — browse files, branches, commits, and repository history.
- **Pull Requests** — create, review, discuss, and merge proposed changes.
- **Issues** — report bugs, track tasks, and discuss work.
- **Notifications** — view activity and updates relevant to you.
- **Organizations and teams** — collaborate on projects across multiple repositories.
- **Settings** — configure repository and account-related options.
- **Projects** — organize and track work using project-management features.

Understanding the interface makes it easier to navigate GitHub and find features related to development, collaboration, code review, and project management.

# GitHub Terminology

Understanding common GitHub terminology is important when working with GitHub repositories and development teams.

## Git

**Git** is a distributed version control system that tracks changes to files and allows multiple people to work on a project.

Git can be used locally without GitHub.

## GitHub

**GitHub** is a web-based platform that hosts Git repositories and provides collaboration features around Git.

GitHub is one of many platforms that can host and work with Git repositories.

## Organization

An **organization (org)** is a shared GitHub account used to manage collaboration across multiple repositories and teams.

Organizations are commonly used by companies, open-source projects, and other groups.

## Repository

A **repository (repo)** is a Git repository containing a project's files and its version-control history.

A GitHub repository typically contains:

- Source code
- Documentation
- Configuration files
- Git history
- Branches
- Issues
- Pull requests

> [!NOTE]  
> A Git repository is not simply a folder containing files. It also contains the Git metadata and history needed for version control.

## Branch

A **branch** is a movable reference to a commit that provides an independent line of development.

Branches allow developers to work on changes without directly modifying another branch.

A repository can have many branches, for example:

```text
main
feature/login
feature/payment
bugfix/session-timeout
```

The **default branch**, commonly named `main`, is often used as the primary integration branch, although the exact workflow depends on the project.

## Fork

A **fork** is a new repository created from an existing repository.

Forks are commonly used when someone wants to contribute to a repository but does not have permission to create branches directly in the original repository.

For example:

```text
Original Repository
       │
       ├── Fork → Your Repository
       │
       └── Pull Request → Original Repository
```

The original repository is often referred to as the **upstream repository**.

## Markdown

**Markdown** is a lightweight markup language used to format plain text.

GitHub uses Markdown extensively for:

- README files
- Documentation
- Issues
- Pull requests
- Comments
- Other repository content

Markdown files commonly use the `.md` extension.

Example:

```markdown
# Project Documentation

This is a **GitHub** project.

- Feature 1
- Feature 2
- Feature 3
```

## Commit

A **commit** is a recorded snapshot of staged changes in a Git repository.

Each commit contains information such as:

- The changes included in the snapshot
- Commit author
- Commit message
- Parent commit(s)
- Commit metadata

Example:

```bash
git add README.md
git commit -m "Update project documentation"
```

## Pull Request

A **Pull Request (PR)** is a request to merge changes from one branch into another.

Pull requests provide a place for team members to:

- Review changes
- Discuss proposed changes
- Request modifications
- Run automated checks
- Approve changes
- Merge the changes

A common workflow is:

```text
Feature Branch
      │
      │ commits
      ▼
Pull Request
      │
      ├── Code Review
      ├── Discussion
      └── Automated Checks
      │
      ▼
Target Branch
```

> [!IMPORTANT]  
> A pull request is a GitHub collaboration mechanism. It is not itself a Git command.

## Merge

A **merge** combines the histories of two branches.

For example:

```text
feature/login
      │
      │
      ▼
   Pull Request
      │
      ▼
     main
```

When a pull request is merged, the changes from the source branch become part of the target branch according to the selected merge method.

The exact deployment behavior depends on the project's CI/CD and hosting setup. Merging a pull request does **not** inherently deploy a website.

## Issues

**Issues** are used to report problems, track tasks, and discuss work.

Examples include:

- Reporting a bug
- Requesting a feature
- Tracking documentation work
- Assigning tasks
- Discussing implementation details

An issue can be assigned to team members and associated with other GitHub features.

## Projects

**GitHub Projects** provides project-management functionality for organizing and tracking work.

Projects can be used to organize issues and other work items for:

- A repository
- An organization
- A larger project spanning multiple repositories

## Wiki

A **Wiki** is a section of a GitHub repository intended for documentation.

However, project documentation can also be maintained directly in the repository using files such as:

```text
README.md
CONTRIBUTING.md
docs/
```

The appropriate documentation approach depends on the project's workflow.

# Typical GitHub Collaboration Workflow

A common GitHub development workflow looks like this:

```text
1. Create Issue
       │
       ▼
2. Create Branch
       │
       ▼
3. Make Changes
       │
       ▼
4. Create Commits
       │
       ▼
5. Open Pull Request
       │
       ▼
6. Review & Discussion
       │
       ▼
7. Automated Checks
       │
       ▼
8. Merge Pull Request
       │
       ▼
9. Deploy / Release
```

The exact workflow varies between teams and projects.

## Step 1 — Create or Select an Issue

A team member creates or selects an issue describing the work to be completed.

For example:

```text
Issue #42
Add login functionality
```

## Step 2 — Create a Branch

Create a branch from the appropriate base branch, often `main`.

```bash
git switch main
git pull
git switch -c feature/login
```

This provides an isolated line of development for the change.

## Step 3 — Make Changes and Create Commits

Make the required changes and commit them to the branch.

```bash
git add .
git commit -m "Add login functionality"
```

Multiple commits can be added to the branch as development continues.

## Step 4 — Open a Pull Request

Push the branch to GitHub:

```bash
git push -u origin feature/login
```

Then create a pull request requesting that the changes be merged into the target branch.

The pull request provides a place for team members to:

- Review the changes
- Discuss implementation details
- Request changes
- Approve the work
- Monitor automated checks

## Step 5 — Review and Merge

After the review process and required automated checks are complete, the pull request can be merged according to the project's workflow.

For example:

```text
feature/login
      │
      │ Pull Request
      ▼
     main
```

If the repository is connected to a deployment pipeline, merging into the target branch may trigger a build or deployment.

> [!NOTE]  
> Deployment is not an inherent part of GitHub's merge operation. It depends on the project's CI/CD and hosting configuration.

# GitHub and Website Publishing

GitHub can be used to manage website content and source code.

A typical workflow is:

```text
Edit Content / Code
        │
        ▼
Git Repository
        │
        ▼
Pull Request
        │
        ▼
Review
        │
        ▼
Merge
        │
        ▼
CI/CD Pipeline
        │
        ▼
Website Deployment
```

Some GitHub-integrated platforms can automatically build and deploy websites from repositories.

One example mentioned in the source material is [Cloud.gov Pages](https://cloud.gov/pages/features/), which can deploy websites from GitHub repositories.

# Collaboration Between Developers and Non-Developers

GitHub is not limited to developers.

Depending on the repository and permissions, team members can use GitHub to:

- Create or edit content
- Report issues
- Review proposed changes
- Discuss work
- Track project tasks
- Maintain documentation

This makes GitHub useful for teams where developers, designers, content creators, project managers, and other contributors need to collaborate.

> [!TIP]  
> For important content, teams may also maintain a master copy in an external document system such as Google Docs or another document-management tool, depending on their workflow.

# GitHub Desktop

[GitHub Desktop](https://desktop.github.com/) is a graphical application for working with Git repositories locally.

It provides a graphical alternative to performing many Git operations from the command line.

For example, GitHub Desktop can help users:

- Clone repositories
- Create branches
- Review changes
- Commit changes
- Push and pull changes
- Create pull requests
- Manage repositories locally

See the [GitHub Desktop documentation](https://docs.github.com/en/desktop/overview/getting-started-with-github-desktop) for more information.

# Git vs. GitHub

|Feature|Git|GitHub|
|---|---|---|
|Type|Version control system|Hosting and collaboration platform|
|Runs locally|Yes|Primarily web-based, with local tools such as GitHub Desktop|
|Tracks file history|Yes|Uses Git repositories|
|Branches|Yes|Yes|
|Commits|Yes|Displays and works with Git commits|
|Merge|Yes|Yes, through Git and GitHub workflows|
|Pull Requests|No native Git concept|Yes|
|Issues|No|Yes|
|Project management|No|Yes|
|Repository hosting|No central hosting required|Yes|
|Code review|Not as a platform feature|Yes|

> [!IMPORTANT]  
> You can use **Git without GitHub**. GitHub is one platform that builds collaboration and repository-hosting features around Git.
