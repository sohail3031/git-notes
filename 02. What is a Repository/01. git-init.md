The git init command creates a new Git repository. It can be used to:

- Convert an existing, unversioned project into a Git repository.    
- Initialize a new, empty Git repository.
- Create a **bare repository** for use as a shared or central repository.
- Initialize repositories using predefined **templates**.

> [!important]  
> `git init` is usually the first Git command you run when starting version control for a new local project.

---

## What Does `git init` Do?

When you run:

```bash
git init
```

Git creates a hidden `.git` directory inside the current working directory.

The `.git` directory contains the metadata required for Git to manage the repository, including information related to:

- Objects    
- References (`refs`)
- Configuration
- Repository templates
- `HEAD`

The `HEAD` file points to the currently checked-out branch or commit.

For example:

```text
my-project/
├── .git/
│   ├── HEAD
│   ├── config
│   ├── objects/
│   ├── refs/
│   └── ...
├── app.py
├── README.md
└── requirements.txt
```

> [!note]  
> `git init` does **not** modify or move the existing project files. It adds the `.git` directory containing Git's repository metadata.

Unlike centralized systems such as SVN, Git does not require a `.git` directory inside every project subdirectory.

---

## Basic Usage

### Initialize the Current Directory

```bash
git init
```

This converts the current directory into a Git repository by creating a `.git` directory.

After this, you can begin tracking files and creating commits.

### Initialize a Specific Directory

```bash
git init <directory>
```

This creates a new directory, if necessary, and initializes an empty Git repository inside it.

For example:

```bash
git init my-project
```

The resulting structure is:

```text
my-project/
└── .git/
```

---

## Running `git init` More Than Once

If a directory is already a Git repository and contains a `.git` directory, you can safely run:

```bash
git init
```

again.

Git will not overwrite the existing repository configuration.

> [!tip]  
> You normally only need to run `git init` once when creating a local repository.

---

# `git init` vs. `git clone`

`git init` and `git clone` can both result in a new Git repository, but they serve different purposes.

|Command|Purpose|
|---|---|
|`git init`|Creates a new Git repository from an existing directory or creates an empty repository|
|`git clone`|Creates a local copy of an existing repository|

### `git init`

Use `git init` when you are starting with a local project that is not yet under Git version control.

```bash
cd my-project
git init
```

### `git clone`

Use `git clone` when a Git repository already exists somewhere else and you want a local copy.

```bash
git clone <repository-url>
```

Internally, `git clone` initializes a new repository and then:

1. Copies repository data from the existing repository.
2. Sets up the remote repository.
3. Checks out the working files.

[Learn more about `git clone`](https://www.atlassian.com/git/tutorials/setting-up-a-repository/git-clone)

> [!important]  
> **Simple rule:**  
> Use `git init` to start a new repository.  
> Use `git clone` to copy an existing repository.

# Bare Repositories

## `git init --bare`

A **bare repository** is a Git repository that does not contain a working directory.

Create one with:

```bash
git init --bare <directory>
```

For example:

```bash
git init --bare my-project.git
```

A bare repository typically contains Git's repository data directly:

```text
my-project.git/
├── HEAD
├── config
├── objects/
├── refs/
└── ...
```

It does **not** contain a checked-out working tree such as:

```text
app.py
README.md
src/
```

### Why Use a Bare Repository?

Bare repositories are commonly used as **shared remote repositories**.

Developers work in their own non-bare local repositories and push their changes to the shared bare repository.

Conceptually:

```text
Developer A
    │
    │ git push
    ▼
Bare Repository
    ▲
    │ git push
    │
Developer B
```

Developers can also clone from the bare repository:

```bash
git clone my-project.git
```

> [!note]  
> A bare repository is primarily intended as a shared Git data store rather than a development workspace.

### Conventional Naming

Bare repositories commonly use the `.git` suffix:

```text
my-project.git
```

---

## Creating a Remote Bare Repository

A common workflow is to connect to a server using SSH and initialize a bare repository:

```bash
ssh <user>@<host>
cd path/above/repo
git init --bare my-project.git
```

The general process is:

1. Connect to the server.
2. Navigate to the location where the repository should be stored.
3. Initialize a bare repository.
4. Developers clone the repository to their local machines.

# Git Init Templates

Git can initialize a repository using a predefined template directory.

### Syntax

```bash
git init <directory> --template=<template_directory>
```

The template directory contains files and directories that Git copies into the new repository's `.git` directory.

Templates can be used to provide repositories with predefined configuration or Git hooks.

---

## Git Hooks and Templates

One useful application of templates is configuring **Git hooks**.

A template can contain predefined hooks that are automatically copied when a new repository is initialized.

For example, an organization could create a template containing standard hooks that are used across its repositories.

[Learn more about Git Hooks](https://www.atlassian.com/git/tutorials/git-hooks)

> [!note]  
> Default Git templates are commonly located under a path similar to:
> 
> ```text
> /usr/share/git-core/templates
> ```
> 
> The exact location may vary depending on the operating system and Git installation.

# `git init` Configuration and Options

The general syntax is:

```bash
git init [<directory>]
```

If a directory is provided, Git initializes the repository inside that directory.

If the directory does not exist, Git can create it.

## `-q` / `--quiet`

Suppresses most output and only displays important messages such as errors and warnings.

```bash
git init --quiet
```

---

## `--bare`

Creates a bare repository without a working directory.

```bash
git init --bare
```

See [Bare Repositories](https://chatgpt.com/c/6aac412f-bc10-83ea-958b-2516684c09f9#bare-repositories).

---

## `--template=<template-directory>`

Specifies a directory containing files and directories to use as a repository template.

```bash
git init --template=<template-directory>
```

---

## `--separate-git-dir=<git-dir>`

Stores the Git repository data separately from the project's working files.

```bash
git init --separate-git-dir=<git-dir>
```

Instead of storing the repository metadata directly in `.git`, Git creates a link file in the project that points to the separate Git directory.

### Example Use Cases

A separate Git directory can be useful when:

- Keeping system configuration files such as `.bashrc` or `.vimrc` in the home directory while storing Git metadata elsewhere.
- Moving a large Git history to a separate high-capacity drive.
- Keeping a Git-managed project in a publicly accessible directory.

You can also use `--separate-git-dir` with an existing repository to move its `.git` directory to another location.

---

## `--shared`

The `--shared` option configures access permissions for a repository intended to be shared by multiple users.

Possible values include:

```text
false
true
umask
group
all
world
everybody
0XXX
```

Example:

```bash
git init --shared=group
```

This option is primarily relevant to repositories shared between users on the same system.

# Examples

## Create a Git Repository for an Existing Project

```bash
cd /path/to/code
git init
git add .
git commit
```

The process is:

1. Navigate to the project directory.
2. Initialize the Git repository.
3. Stage the project files.
4. Create the first commit.

---

## Create a New Bare Repository

```bash
git init --bare /path/to/repo.git
```

This creates a bare repository that can be used as a shared Git repository.

---

## Create a Repository from a Template

Create a template directory:

```bash
mkdir -p /path/to/template
```

Add a file to the template:

```bash
echo "Hello World" >> /absolute/path/to/template/README
```

Initialize a new repository using the template:

```bash
git init /new/repo/path --template=/absolute/path/to/template
```

Navigate to the new repository:

```bash
cd /new/repo/path
```

Verify the copied file:

```bash
cat /new/repo/path/README
```

# `git init` Quick Reference

|Command|Description|
|---|---|
|`git init`|Initialize a repository in the current directory|
|`git init <directory>`|Initialize a repository in a specific directory|
|`git init --bare <directory>`|Create a bare repository|
|`git init --quiet`|Suppress most output|
|`git init --template=<dir>`|Initialize using a repository template|
|`git init --separate-git-dir=<dir>`|Store Git metadata separately|
|`git init --shared=<value>`|Configure permissions for a shared repository|

> [!summary]  
> **Key takeaway:** `git init` creates the Git metadata needed to turn a directory into a Git repository. For normal development, use `git init` in your project directory. For a shared repository that acts primarily as a remote data store, use `git init --bare`.
