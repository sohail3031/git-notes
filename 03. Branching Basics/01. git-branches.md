Git branches are a fundamental part of working with version control. They allow developers to work on different features, experiments, or bug fixes without directly affecting the main codebase.

Branches can be created and managed through the terminal or through graphical interfaces such as GitHub.

---

# What Is a Git Branch?

A Git branch is essentially a **movable pointer to a commit**.

When you create a branch, Git does not copy the entire project. Instead, it creates a new reference pointing to an existing commit.

For example:

```text
A --- B --- C
            ↑
           main
```

If you create a new branch:

```bash
git branch feature-login
```

the history remains unchanged:

```text
A --- B --- C
            ↑
          main
            ↑
      feature-login
```

Both branches initially point to the same commit.

Once you switch to the new branch and create commits, the histories diverge:

```text
A --- B --- C --- D --- E
            ↑           ↑
          main     feature-login
```

The branch `feature-login` now points to a newer commit, while `main` remains at commit `C`.

# Why Use Branches?

Branches provide an isolated line of development.

For example, you may create separate branches for:

- New features    
- Bug fixes
- Experiments
- Refactoring
- Documentation changes
- Testing new ideas

A common workflow is:

```text
main
  │
  ├── feature-login
  │
  ├── bugfix-payment
  │
  └── documentation
```

This allows multiple pieces of work to progress independently.

> [!NOTE]  
> Branches help keep unfinished or experimental work separate from the main development line until it is ready to be merged.

---

# Git Branches Are Lightweight

Branches in Git are much more lightweight than branches in many older version control systems.

Git does not create a complete copy of your project when you create a branch.

Instead, a branch is essentially a reference to a commit.

```text
Branch
   ↓
Commit
   ↓
Parent Commit
   ↓
Parent Commit
   ↓
...
```

The history of a branch is determined by the relationships between its commits.

> [!IMPORTANT]  
> A branch is **not a container that stores commits**. It is a reference pointing to a particular commit, usually the latest commit in that line of development.

---

# Branches and the Development Workflow

A branch provides an independent line of development.

Conceptually, you can think of a branch as allowing you to work independently with:

- Working directory    
- Staging area
- Commit history

When you create commits on a branch, the branch pointer moves forward.

For example:

```text
A --- B --- C
            ↑
          main
```

After switching to a new branch and creating two commits:

```text
A --- B --- C --- D --- E
            ↑           ↑
          main      feature
```

The `feature` branch has moved forward while `main` remains unchanged.

# The `git branch` Command

The `git branch` command is used primarily to:

- Create branches    
- List branches
- Rename branches
- Delete branches

It does **not** switch between branches.

Commands such as `git switch` or `git checkout` are used to switch branches.

Branch histories can be combined using commands such as `git merge`.

---

# Common `git branch` Commands

## List Local Branches

```bash
git branch
```

This lists the local branches in the repository.

The current branch is marked with an asterisk:

```text
* main
  feature-login
  bugfix-payment
```

You can also use:

```bash
git branch --list
```

---

## Create a New Branch

```bash
git branch <branch>
```

For example:

```bash
git branch feature-login
```

This creates a new branch called `feature-login`.

> [!IMPORTANT]  
> `git branch <branch>` **creates** the branch but does not switch to it.

To start working on the new branch, switch to it using:

```bash
git switch feature-login
```

or, with the older `checkout` command:

```bash
git checkout feature-login
```

A more convenient modern command combines creation and switching:

```bash
git switch -c feature-login
```

# Creating a Branch

Suppose your repository currently looks like this:

```text
A --- B --- C
            ↑
           main
```

Create a branch:

```bash
git branch crazy-experiment
```

The repository history remains unchanged:

```text
A --- B --- C
            ↑
          main
            ↑
     crazy-experiment
```

Only a new branch reference has been created.

To begin making commits on the new branch:

```bash
git switch crazy-experiment
```

Then use the normal workflow:

```bash
git add <file>
git commit -m "add experimental feature"
```

The history now becomes:

```text
A --- B --- C --- D
            ↑       ↑
          main   crazy-experiment
```

# List Remote Branches

To list remote-tracking branches:

```bash
git branch -r
```

To list both local and remote branches:

```bash
git branch -a
```

Example:

```text
* main
  feature-login
  remotes/origin/main
  remotes/origin/feature-login
```

---

# Rename a Branch

To rename the current branch:

```bash
git branch -m <new-name>
```

For example:

```bash
git branch -m feature-authentication
```

You can also rename another local branch:

```bash
git branch -m <old-name> <new-name>
```

Example:

```bash
git branch -m old-feature new-feature
```

---

# Deleting a Branch

After completing and merging a branch, you can delete the local branch:

```bash
git branch -d <branch>
```

For example:

```bash
git branch -d feature-login
```

The `-d` option performs a safety check. Git normally prevents deletion if the branch contains commits that have not been merged into another branch.

Example error:

```text
error: The branch 'feature-login' is not fully merged.
If you are sure you want to delete it, run 'git branch -D feature-login'.
```

This protection helps prevent accidental loss of access to work.

---

# Force Delete a Branch

If you intentionally want to delete an unmerged branch:

```bash
git branch -D <branch>
```

For example:

```bash
git branch -D crazy-experiment
```

The `-D` option forcefully deletes the local branch, even if Git determines that it contains unmerged commits.

> [!WARNING]  
> Use `git branch -D` carefully. Make sure you no longer need the commits that are reachable only through that branch.

---

# Local vs. Remote Branch Deletion

The commands above delete **local branches**.

Deleting a local branch does not automatically delete the corresponding branch on a remote repository.

To delete a remote branch:

```bash
git push origin --delete crazy-experiment
```

This tells the remote repository to delete the branch.

An older alternative syntax is:

```bash
git push origin :crazy-experiment
```

The modern and clearer form is:

```bash
git push origin --delete crazy-experiment
```

---

# Creating Remote Branches

Branches can also be pushed to a remote repository.

First, make sure a remote repository is configured.

You can add a remote with:

```bash
git remote add origin https://example.com/user/repository.git
```

Then push a local branch:

```bash
git push origin crazy-experiment
```

This creates or updates the `crazy-experiment` branch on the remote repository.

A common pattern is:

```bash
git push -u origin crazy-experiment
```

The `-u` option establishes the remote-tracking relationship between the local branch and the remote branch.

After the upstream is configured, future pushes can usually be performed with:

```bash
git push
```

# Branching Workflow

A typical feature-branch workflow looks like this:

```text
             ┌── feature-login ── D ── E
             │
A ── B ── C ─┤
             │
             └── main
```

### Step 1: Check the current branch

```bash
git status
```

### Step 2: Create and switch to a new branch

```bash
git switch -c feature-login
```

### Step 3: Make changes

Edit or create files in your working directory.

### Step 4: Stage the changes

```bash
git add <file>
```

### Step 5: Commit the changes

```bash
git commit -m "add login feature"
```

### Step 6: Push the branch

```bash
git push -u origin feature-login
```

### Step 7: Merge the branch when the work is ready

For example, after switching back to `main`:

```bash
git switch main
git merge feature-login
```

### Step 8: Delete the branch if it is no longer needed

```bash
git branch -d feature-login
```

# Important Branch Concepts

| Concept        | Description                                                         |
| -------------- | ------------------------------------------------------------------- |
| Branch         | A movable reference pointing to a commit                            |
| `main`         | Common default name for the primary branch                          |
| `HEAD`         | Reference to the currently checked-out branch or commit             |
| Local branch   | A branch stored in your local repository                            |
| Remote branch  | A branch maintained on a remote repository                          |
| `git branch`   | Creates, lists, renames, and deletes branches                       |
| `git switch`   | Switches between branches                                           |
| `git checkout` | Older command that can switch branches and perform other operations |
| `git merge`    | Combines histories from different branches                          |
| `git push`     | Sends local commits/branches to a remote repository                 |

# Common Branch Commands

| Command                           | Purpose                                 |
| --------------------------------- | --------------------------------------- |
| `git branch`                      | List local branches                     |
| `git branch -a`                   | List local and remote-tracking branches |
| `git branch -r`                   | List remote-tracking branches           |
| `git branch <name>`               | Create a new branch                     |
| `git switch <name>`               | Switch to an existing branch            |
| `git switch -c <name>`            | Create and switch to a new branch       |
| `git branch -m <name>`            | Rename the current branch               |
| `git branch -m <old> <new>`       | Rename another local branch             |
| `git branch -d <name>`            | Safely delete a local branch            |
| `git branch -D <name>`            | Force-delete a local branch             |
| `git push -u origin <name>`       | Push a branch and set its upstream      |
| `git push origin --delete <name>` | Delete a remote branch                  |

# Git Branch vs. Other Version Control Systems

Branching in Git is designed to be lightweight and inexpensive, which makes branches practical for everyday development.

Rather than creating a complete copy of a project for every branch, Git primarily creates and updates references to commits.

This makes workflows such as **feature branches** practical:

```text
main
 │
 ├── feature-A
 │
 ├── feature-B
 │
 └── bugfix-C
```

Developers can work on these branches independently and later merge the completed work into the appropriate branch.

# Key Takeaways

- A Git branch is essentially a **movable pointer to a commit**.    
- Creating a branch does not copy the entire repository.
- Branches provide separate lines of development.
- Branches are useful for features, bug fixes, experiments, and other isolated work.
- `git branch` can create, list, rename, and delete branches.
- `git branch <name>` creates a branch but does not switch to it.
- `git switch <name>` switches to an existing branch.
- `git switch -c <name>` creates and switches to a new branch.
- `git checkout <name>` can also switch branches and is commonly seen in older Git workflows.
- `git branch -d <name>` safely deletes a merged branch.
- `git branch -D <name>` force-deletes a branch.
- Local branch deletion does not automatically delete the remote branch.
- `git push origin --delete <name>` deletes a branch from the remote repository.
- `git merge` combines histories from different branches.
- Branches make it easier to keep unfinished or experimental work separate from the main development line.
