Viewing commit history shows the sequence of commits made to a repository. The most common command for viewing this history is:

```bash
git log
```

Each commit typically includes information such as:

- Commit hash    
- Author
- Date
- Commit message

Commit history helps developers:

- Understand how a project evolved.
- Review previous changes.
- Find when a bug or change was introduced.
- Review another developer's work.
- Compare different points in the project's history.
- Investigate or recover previous states of a project.

---

# `git log`

After creating several commits, or after cloning a repository that already has a commit history, you can use `git log` to inspect the history.

For example:

```bash
git log
```

By default, `git log` displays commits in **reverse chronological order**, meaning the most recent commit appears first.

A typical output looks like:

```text
commit ca82a6dff817ec66f44342007202690a93763949
Author: Scott Chacon <schacon@gee-mail.com>
Date:   Mon Mar 17 21:52:11 2008 -0700

    Change version number

commit 085bb3bcb608e1e8451d4b2432f8ecbe6306e7e7
Author: Scott Chacon <schacon@gee-mail.com>
Date:   Sat Mar 15 16:40:33 2008 -0700

    Remove unnecessary test

commit a11bef06a3f659402fe7563abf99ad00de2209e6
Author: Scott Chacon <schacon@gee-mail.com>
Date:   Sat Mar 15 10:31:28 2008 -0700

    Initial commit
```

Each entry includes:

- The commit's SHA hash    
- Author name and email
- Commit date
- Commit message

# Viewing Changes Introduced by Commits

## `git log -p`

The `-p` or `--patch` option displays the changes introduced by each commit.

```bash
git log -p
```

This displays the commit information followed by the corresponding diff.

For example:

```bash
git log -p -2
```

This shows the changes introduced by the **two most recent commits**.

The output contains information such as:

```text
commit ca82a6dff817ec66f44342007202690a93763949
Author: Scott Chacon <schacon@gee-mail.com>
Date:   Mon Mar 17 21:52:11 2008 -0700

    Change version number

diff --git a/Rakefile b/Rakefile
index a874b73..8f94139 100644
--- a/Rakefile
+++ b/Rakefile
@@ -5,7 +5,7 @@ require 'rake/gempackagetask'
 spec = Gem::Specification.new do |s|
     s.platform  =   Gem::Platform::RUBY
     s.name      =   "simplegit"
-    s.version   =   "0.1.0"
+    s.version   =   "0.1.1"
     s.author    =   "Scott Chacon"
```

This is useful for:

- Code review.    
- Understanding what changed in a commit.
- Quickly browsing changes made over a series of commits.

# Limiting the Number of Commits

You can specify the number of commits to display by using:

```bash
git log -<n>
```

For example:

```bash
git log -2
```

displays the two most recent commits.

Similarly:

```bash
git log -5
```

displays the five most recent commits.

# Viewing Commit Statistics

## `git log --stat`

The `--stat` option displays a summary of the files changed by each commit.

```bash
git log --stat
```

Example:

```text
commit ca82a6dff817ec66f44342007202690a93763949
Author: Scott Chacon <schacon@gee-mail.com>
Date:   Mon Mar 17 21:52:11 2008 -0700

    Change version number

 Rakefile | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

The statistics show:

- Files that were modified.    
- Number of insertions.
- Number of deletions.

For example:

```text
3 files changed, 54 insertions(+)
```

means that three files were changed and 54 lines were added.

# Formatting `git log` Output

The `--pretty` option allows you to customize the format of the commit history.

```bash
git log --pretty=<format>
```

Some built-in formats include:

- `oneline`    
- `short`
- `full`
- `fuller`
- `format`

---

## `git log --pretty=oneline`

The `oneline` format displays each commit on a single line.

```bash
git log --pretty=oneline
```

Example:

```text
ca82a6dff817ec66f44342007202690a93763949 Change version number
085bb3bcb608e1e8451d4b2432f8ecbe6306e7e7 Remove unnecessary test
a11bef06a3f659402fe7563abf99ad00de2209e6 Initial commit
```

This is useful when you want to quickly scan a large number of commits.

---

## `git log --oneline`

A convenient shorthand is:

```bash
git log --oneline
```

`--oneline` is equivalent to:

```bash
git log --pretty=oneline --abbrev-commit
```

It displays an abbreviated commit hash and the commit message.

Example:

```text
ca82a6d Change version number
085bb3b Remove unnecessary test
a11bef0 Initial commit
```

---

# Custom Log Formats

The `format` option allows you to define exactly what information should be displayed.

```bash
git log --pretty=format:"%h - %an, %ar : %s"
```

Example:

```text
ca82a6d - Scott Chacon, 6 years ago : Change version number
085bb3b - Scott Chacon, 6 years ago : Remove unnecessary test
a11bef0 - Scott Chacon, 6 years ago : Initial commit
```

This is particularly useful when generating output for scripts or other tools because you explicitly define the format.

---

# `git log --pretty=format` Specifiers

| Specifier | Description               |
| --------- | ------------------------- |
| `%H`      | Commit hash               |
| `%h`      | Abbreviated commit hash   |
| `%T`      | Tree hash                 |
| `%t`      | Abbreviated tree hash     |
| `%P`      | Parent hashes             |
| `%p`      | Abbreviated parent hashes |
| `%an`     | Author name               |
| `%ae`     | Author email              |
| `%ad`     | Author date               |
| `%ar`     | Author date, relative     |
| `%cn`     | Committer name            |
| `%ce`     | Committer email           |
| `%cd`     | Committer date            |
| `%cr`     | Committer date, relative  |
| `%s`      | Commit subject            |

Useful documentation:

[Git `pretty-format` documentation](https://git-scm.com/docs/pretty-formats)

# Author vs. Committer

Git distinguishes between an **author** and a **committer**.

### Author

The author is the person who originally wrote the changes.

### Committer

The committer is the person who actually created the commit containing those changes.

For example, suppose a developer creates a patch and sends it to a project maintainer. If the maintainer applies the patch and creates the commit:

```text
Author:     Original developer
Committer:  Project maintainer
```

Both people are represented in the commit metadata.

# Visualizing Branches and Merges

## `git log --graph`

The `--graph` option displays an ASCII graph showing branch and merge relationships.

For example:

```bash
git log --pretty=format:"%h %s" --graph
```

Example output:

```text
* 2d3acf9 Ignore errors from SIGCHLD on trap
* 5e3ee11 Merge branch 'master'
|\
| * 420eac9 Add method for getting the current branch
* | 30e367c Timeout code and tests
* | 5a09431 Add timeout protection to grit
* | e1193f8 Support for heads with slashes in them
|/
* d6016bc Require time for xmlschema
* 11d191e Merge branch 'defunkt' into local
```

The graph becomes particularly useful when working with **branches and merges**.

A common command is:

```bash
git log --oneline --graph
```

You can also include all branches:

```bash
git log --oneline --graph --all
```

| `--oneline`       | Display abbreviated commit hashes and commit messages on one line.                |

# Limiting Log Output

In addition to formatting the output, `git log` provides options for limiting which commits are displayed.

## Show the Last N Commits

```bash
git log -<n>
```

Examples:

```bash
git log -2
```

```bash
git log -10
```

The first command displays the last two commits, while the second displays the last ten.

---

# Filtering by Date

You can use `--since` and `--until` to limit commits to a specific time period.

## `--since`

```bash
git log --since=2.weeks
```

This displays commits made within the last two weeks.

You can also specify a particular date:

```bash
git log --since="2008-01-15"
```

Relative dates can also be used:

```bash
git log --since="2 years 1 day 3 minutes ago"
```

## `--until`

```bash
git log --until="2026-09-01"
```

This limits the results to commits made before the specified date.

### Related Options

| Option                 | Description                                  |
| ---------------------- | -------------------------------------------- |
| `--since` / `--after`  | Show commits made after the specified date.  |
| `--until` / `--before` | Show commits made before the specified date. |

---

# Filtering by Author

The `--author` option allows you to find commits made by a specific author.

```bash
git log --author="Scott Chacon"
```

You can also combine it with other options:

```bash
git log --author="Scott Chacon" --since="2026-01-01"
```

---

# Filtering by Commit Message

The `--grep` option searches commit messages for a specific string.

```bash
git log --grep="authentication"
```

This displays commits whose commit messages contain `authentication`.

You can specify multiple `--grep` options.

By default, multiple `--grep` patterns can match any of the specified patterns. To require a commit message to match **all** of the patterns, use:

```bash
git log --all-match --grep="authentication" --grep="login"
```

---

# Finding Changes with `-S`

The `-S` option is sometimes called the **pickaxe** option.

It searches for commits that changed the number of occurrences of a specified string.

For example:

```bash
git log -S "function_name"
```

This can help you find commits where a particular function, variable, or piece of text was added or removed.

It is particularly useful when you know the name of something that changed but do not know which commit introduced the change.

---

# Viewing History for a Specific File

You can limit the log to commits that affected a specific file or directory.

Use `--` to separate Git options from file paths:

```bash
git log -- path/to/file
```

For example:

```bash
git log -- src/login.py
```

This displays commits that changed `src/login.py`.

You can also specify a directory:

```bash
git log -- src/
```

### Why Use `--`?

The double dash tells Git that what follows should be interpreted as a **path**, rather than as another command-line option.

---

# Combining Multiple Filters

Git allows you to combine several filtering and formatting options.

For example:

```bash
git log --pretty="%h - %s" \
  --author="Junio C Hamano" \
  --since="2008-10-01" \
  --before="2008-11-01" \
  --no-merges \
  -- t/
```

This command:

- Displays abbreviated commit hashes.    
- Displays commit subjects.
- Filters by author.
- Limits commits to a date range.
- Excludes merge commits.
- Limits the results to changes under the `t/` directory.

---

# Options for Limiting `git log` Output

| Option                | Description                                                          |
| --------------------- | -------------------------------------------------------------------- |
| `-<n>`                | Show only the last `n` commits.                                      |
| `--since`, `--after`  | Show commits made after the specified date.                          |
| `--until`, `--before` | Show commits made before the specified date.                         |
| `--author`            | Show commits where the author matches the specified string.          |
| `--committer`         | Show commits where the committer matches the specified string.       |
| `--grep`              | Show commits whose commit messages contain the specified string.     |
| `-S`                  | Show commits that add or remove occurrences of the specified string. |
| `-- <path>`           | Show commits affecting the specified file or directory.              |
| `--no-merges`         | Exclude merge commits from the output.                               |

# Excluding Merge Commits

In repositories that use frequent branching and merging, the commit history may contain many merge commits.

To hide merge commits:

```bash
git log --no-merges
```

This can make the history easier to read when you are primarily interested in commits containing direct changes.

You can combine it with other options:

```bash
git log --oneline --no-merges
```

Or:

```bash
git log --oneline --graph --no-merges
```

# Key Takeaways

- `git log` is the primary command for viewing commit history.    
- By default, commits are displayed in reverse chronological order.
- Each commit includes information such as its hash, author, date, and message.
- `git log -p` shows the changes introduced by each commit.
- `git log --stat` shows statistics about changed files and lines.
- `git log --oneline` provides a compact history.
- `git log --graph` displays an ASCII representation of branch and merge history.
- `git log --all` allows you to view commits from all references, including branches.
- `--since` and `--until` filter commits by date.
- `--author` filters commits by author.
- `--committer` filters commits by committer.
- `--grep` searches commit messages.
- `-S` searches for commits that changed the number of occurrences of a specific string.
- `git log -- <path>` displays history for a specific file or directory.
- `--no-merges` excludes merge commits.
- `--pretty=format:` allows you to customize the information displayed for each commit.
- The **author** is the person who originally created the work, while the **committer** is the person who created the commit containing that work.
