# Working Directory

The **working directory** is the actual folder on disk where a developer works on a project.

It contains the current state of the project's files, including changes that have:

- Not yet been staged
- Been staged but not committed
- Already been committed

Git compares the working directory with the **staging area** and the latest commit to determine what has changed.

---

# Working Directory vs. Git Directory

A Git repository contains different areas that serve different purposes. The **working directory** is where you edit project files, while the **Git directory** stores Git's repository metadata.

> [!important]  
> The working directory is where you work on your project. The Git directory is where Git stores information needed to manage the repository.

## Creator

### Working Directory

A working directory is a folder created by the developer to store project files.

For example:

```text
my-project/
├── app.py
├── README.md
└── requirements.txt
```

### Git Directory

When you run:

```bash
git init
```

Git creates a `.git` directory inside the project.

```text
my-project/
├── .git/
├── app.py
├── README.md
└── requirements.txt
```

The `.git` directory contains Git's repository metadata.

---

# Visibility

### Working Directory

The working directory is a normal, visible folder containing your project files.

### Git Directory

The `.git` directory is normally hidden because its name begins with a dot on Unix-like systems.

On Windows, its visibility depends on your file-explorer settings and Git configuration.

---

# Purpose

### Working Directory

The working directory contains the files you are actively working on.

It can contain:

- Tracked files
- Untracked files
- Modified files
- New files
- Deleted files

### Git Directory

The `.git` directory stores Git's internal repository information, such as:

- Commit history
- Branch information
- References
- Repository configuration
- Objects
- `HEAD`

> [!note]  
> The `.git` directory does not simply contain copies of all tracked files. It contains the metadata and Git objects that allow Git to manage the repository and its history.

---

# Location

The working directory can be created anywhere on your computer.

For example:

```text
C:\Users\username\Projects\my-project
```

or:

```text
/home/username/projects/my-project
```

When a normal Git repository is initialized, Git creates the `.git` directory inside the working directory:

```text
my-project/
├── .git/
├── src/
├── tests/
└── README.md
```

# Tracked vs. Untracked Files

One of the most important concepts when understanding the working directory is the difference between **tracked** and **untracked** files.

## Tracked Files

A tracked file is a file that Git knows about.

A file becomes tracked when it is added to the staging area:

```bash
git add <file>
```

and eventually committed:

```bash
git commit -m "Add file"
```

Tracked files can have different states, such as:

- Unmodified
- Modified
- Staged

## Untracked Files

An untracked file is a file that exists in the working directory but Git is not currently tracking.

For example:

```text
my-project/
├── README.md
├── app.py
└── notes.txt
```

If `notes.txt` has never been added to Git, it is untracked.

You can check the status of files with:

```bash
git status
```

# Working Directory and Git Workflow

A simplified Git workflow looks like this:

```text
Working Directory
       │
       │ git add
       ▼
Staging Area
       │
       │ git commit
       ▼
Git Repository
```

### 1. Working Directory

You create or modify files here.

```text
app.py
```

### 2. Staging Area

You select changes to include in the next commit:

```bash
git add app.py
```

### 3. Repository

You permanently record the staged changes in Git's history:

```bash
git commit -m "Update application"
```

# Example

Suppose you have a Git repository:

```text
my-project/
├── .git/
├── app.py
└── README.md
```

You modify `app.py`.

The change initially exists only in the **working directory**.

Check the status:

```bash
git status
```

Git may report:

```text
modified: app.py
```

Stage the change:

```bash
git add app.py
```

Now the change is in the **staging area**.

Finally, create a commit:

```bash
git commit -m "Update app"
```

The change is now recorded in the Git repository's history.

# Working Directory vs. Git Directory

|Feature|Working Directory|Git Directory|
|---|---|---|
|Purpose|Where you work on project files|Stores Git repository metadata|
|Created by|Developer|Git|
|Typical name|Project folder|`.git`|
|Visibility|Normal/visible|Usually hidden|
|Contains|Tracked and untracked project files|Git objects, refs, configuration, history metadata|
|Main activity|Editing files|Managing Git history and repository state|
|Example|`my-project/`|`my-project/.git/`|

> [!tip]  
> Remember the distinction:
> 
> **Working directory → where you edit files**  
> **Staging area → where you prepare changes**  
> **Git repository → where Git records committed history**
