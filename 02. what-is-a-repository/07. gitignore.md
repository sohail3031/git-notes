# Ignoring Files

Git allows you to specify files and directories that should **not be tracked** by Git. These rules are typically defined in a special file named `.gitignore`.

There is no `git ignore` command. Instead, you create or edit a `.gitignore` file and commit it to the repository when you want the ignore rules to be shared with other contributors.

A `.gitignore` file contains **patterns** that Git uses to determine which files and directories should be ignored.

> [!NOTE]  
> `.gitignore` primarily affects **untracked files**. If a file is already tracked by Git, adding it to `.gitignore` does not automatically stop Git from tracking it.

---

# Configuring Ignored Files for a Single Repository

Create a `.gitignore` file in the **root directory** of your repository.

For example:

```text
my-project/
├── .git/
├── .gitignore
├── README.md
└── src/
```

The `.gitignore` file can contain patterns for files and directories that should not be tracked.

### Example

```gitignore
# Python cache files
__pycache__/
*.pyc

# Environment variables
.env

# IDE files
.vscode/

# Build output
dist/
build/
```

After creating or modifying `.gitignore`, commit it if you want the rules to be shared with other developers who clone the repository.

```bash
git add .gitignore
git commit -m "add gitignore rules"
```

---

# Creating a `.gitignore` File

From the terminal, navigate to the root of your Git repository and create the file:

```bash
touch .gitignore
```

If the command succeeds, it normally produces no output.

On Windows, you can also create `.gitignore` using a text editor or through Git Bash.

---

# Sharing `.gitignore` Rules

A repository-level `.gitignore` file can be committed to the repository.

This means that when other developers clone the repository, they also receive the same ignore rules.

For example:

```bash
git add .gitignore
git commit -m "add gitignore configuration"
git push
```

This is useful for files that should generally be ignored by everyone working on the project, such as:

- Build artifacts
- Dependency directories
- IDE configuration files
- Operating-system-generated files
- Temporary files
- Local environment files

---

# `.gitignore` Templates

GitHub maintains a collection of recommended `.gitignore` templates for many programming languages, frameworks, operating systems, and development environments.

You can find them in the [github/gitignore](https://github.com/github/gitignore) repository.

Another resource is [gitignore.io](https://www.gitignore.io/), which can generate `.gitignore` rules based on your:

- Operating system
- Programming language
- IDE
- Development environment

For example, a Python project might use rules for:

```gitignore
__pycache__/
*.pyc
.venv/
.env
```

A Java project might have different rules, while an IntelliJ IDEA project may require IDE-specific patterns.

---

# Example `.gitignore` Configuration

A simple `.gitignore` might look like:

```gitignore
# Python
__pycache__/
*.pyc
.venv/

# Environment variables
.env

# IDE
.vscode/
.idea/

# Operating system
.DS_Store
Thumbs.db

# Build output
build/
dist/
```

> [!TIP]  
> Never blindly copy a `.gitignore` template. Review the rules and make sure they match the needs of your project.

# Ignoring a File That Is Already Tracked

Adding a file to `.gitignore` does **not** remove it from Git if Git is already tracking it.

For example, suppose you committed:

```text
.env
```

and later add this to `.gitignore`:

```gitignore
.env
```

Git will continue tracking `.env` because it is already part of the repository's tracked files.

You must first remove it from Git's index while keeping the file on your local computer:

```bash
git rm --cached .env
```

Then add the rule to `.gitignore`:

```gitignore
.env
```

Finally, commit the changes:

```bash
git add .gitignore
git commit -m "ignore environment file"
```

### Important

`git rm --cached` removes the file from Git's **staging area/index**, but does not delete the local file from your working directory.

# Global Git Ignore Rules

You can also configure Git to ignore certain files or directories across **all repositories on your computer**.

This can be useful for files that are generated locally by your operating system, editor, or development tools.

Examples include:

```text
.DS_Store
Thumbs.db
*.swp
```

Global ignore rules are useful when the files are specific to your local environment and should not normally be included in any repository.

A common global excludes file is:

```text
~/.config/git/ignore
```

You can create the necessary directories and file if they do not already exist.

> [!NOTE]  
> The exact location of Git's global excludes file can vary depending on your operating system and Git configuration. You can configure the location explicitly with `core.excludesFile`.

For example:

```bash
git config --global core.excludesFile ~/.config/git/ignore
```

Then add global ignore patterns to:

```text
~/.config/git/ignore
```

These rules apply to repositories on your local computer but are **not committed** to individual repositories.

---

# Local Ignore Rules with `.git/info/exclude`

Sometimes you want to ignore files **only in your local repository** without modifying the repository's `.gitignore` file.

For this situation, Git provides:

```text
.git/info/exclude
```

This file is inside the repository's `.git` directory:

```text
.git/
└── info/
    └── exclude
```

Rules added to `.git/info/exclude`:

- Apply only to the current repository.
- Are not committed.
- Are not shared with other developers.

This is useful for locally generated files that other contributors are unlikely to have.

### Example

Suppose your local development environment creates:

```text
local-notes.txt
```

You can add this to:

```text
.git/info/exclude
```

```gitignore
local-notes.txt
```

Git will ignore the file in your local repository without modifying the project's shared `.gitignore`.

---

# Three Ways to Ignore Files

|Method|Scope|Shared with others?|Typical Use|
|---|---|---|---|
|`.gitignore`|One repository|Yes, when committed|Project-specific files|
|Global ignore file|All repositories on your computer|No|Personal OS/editor files|
|`.git/info/exclude`|One local repository|No|Repository-specific personal files|

---

# `.gitignore` vs `.git/info/exclude`

### `.gitignore`

Use `.gitignore` when:

- The entire project should ignore the files.
- Other developers should use the same rules.
- The rules should be committed to the repository.

### `.git/info/exclude`

Use `.git/info/exclude` when:

- Only you need the ignore rule.
- The rule should not be shared.
- You do not want to modify the project's `.gitignore`.

---

# Important `.gitignore` Concepts

- `.gitignore` contains patterns that tell Git which **untracked** files and directories to ignore.
- There is no `git ignore` command.
- A repository-level `.gitignore` is normally stored in the repository and can be committed.
- `.gitignore` rules are inherited through directory structure and can also be placed in subdirectories.
- Adding a tracked file to `.gitignore` does not automatically stop tracking it.
- Use `git rm --cached <file>` to remove a tracked file from Git's index while keeping the local file.
- Global ignore rules apply across repositories on your computer.
- `.git/info/exclude` provides repository-specific ignore rules that are not committed.
- Never put passwords, API keys, or other secrets into a repository merely because they are listed in `.gitignore`. Ignoring a file does not protect a secret that has already been committed.
