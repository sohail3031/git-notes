# Local vs. Global Git Configuration

Git configuration can be defined at different levels. Two commonly used levels are:

- **Local** — applies only to the current repository.
- **Global** — applies to every repository for the current user.

## Local Configuration

Local configuration applies only to the current Git repository.

It is stored inside the repository at:

```text
.git/config
```

For example:

```bash
git config user.name "Your Name"
```

Because no `--global` option is specified, this setting applies only to the current repository.

## Global Configuration

Global configuration applies to every Git repository for the current user.

It is typically stored in:

```text
~/.gitconfig
```

Global configuration is commonly used for default settings such as:

- User name
- User email
- Default editor
- Default initial branch name
- Git aliases
- Fetch behavior
- Merge and diff tools

## Local vs. Global Configuration

If the same setting exists at both levels, the **local repository configuration takes precedence over the global configuration**.

|Configuration|Scope|Typical Location|
|---|---|---|
|System|All users on the computer|System Git configuration|
|Global|Current user, all repositories|`~/.gitconfig`|
|Local|Current repository only|`.git/config`|

> [!important]  
> A local configuration can override a global configuration for the same property.

# Configure Your Global Git Identity

The first configuration step after installing Git is usually setting your name and email.

```bash
git config --global user.name "Your Name"
git config --global user.email "your_email@example.com"
```

These values are stored in your Git configuration and are used when creating commits.

### Using `--add`

You can explicitly add a configuration value using `--add`:

```bash
git config --global --add user.name "Your Name"
git config --global --add user.email "your_email@example.com"
```

> [!note]  
> `--add` is useful when you intentionally want to add another value. For ordinary identity configuration, `git config --global user.name ...` and `git config --global user.email ...` are generally sufficient.

# Configure the Default Git Editor

Git may open a text editor when you perform operations that require you to enter or edit a message, such as creating a commit or tag.

You can configure the default editor with:

```bash
git config --global core.editor "vim"
```

For example, you could configure another editor by specifying its command:

```bash
git config --global core.editor "code --wait"
```

> [!tip]  
> The editor command depends on which text editor you have installed and how it is configured on your system.

---

# Configure the Default Initial Branch

Historically, Git commonly used `master` as the default initial branch name.

Since Git 2.28, you can configure the default name used when creating a new repository.

For example, to use `main`:

```bash
git config --global init.defaultBranch main
```

After this configuration, running:

```bash
git init
```

will create the initial branch as:

```text
main
```

> [!important]  
> `init.defaultBranch` affects repositories created after the setting is configured. It does not rename branches in existing repositories.

# Automatically Prune During Fetch

Git can remove references to remote branches that no longer exist on the remote repository.

You can manually prune during a fetch:

```bash
git fetch --prune
```

You can also configure Git to prune automatically whenever you run `git fetch`:

```bash
git config --global fetch.prune true
```

After enabling this setting:

```bash
git fetch
```

will automatically prune stale remote-tracking references.

> [!note]  
> `git prune` is a lower-level housekeeping command that removes unreachable Git objects. `git fetch --prune` deals with stale remote-tracking references, so these operations should not be treated as the same thing.

---

# Configure Git Merge and Diff Tools

When Git encounters a merge conflict, you can use a merge tool to help resolve the conflict.

You can configure an external merge tool with:

```bash
git config --global merge.tool kdiff3
```

Or:

```bash
git config --global merge.tool p4merge
```

You can also configure an external diff tool:

```bash
git config --global diff.tool kdiff3
```

Or:

```bash
git config --global diff.tool p4merge
```

> [!note]  
> The tool must be installed on your system and properly configured for Git to use it.

# Git Aliases

Git aliases allow you to create shortcuts for frequently used commands.

For example:

```bash
git config --global alias.st status
```

After creating this alias:

```bash
git st
```

will execute:

```bash
git status
```

## Common Git Aliases

### Shorter `status`

```bash
git config --global alias.st 'status -sb'
```

### Shorter `checkout`

```bash
git config --global alias.co checkout
```

### Shorter `commit -m`

```bash
git config --global alias.cm 'commit -m'
```

Usage:

```bash
git cm "Add login tests"
```

### Shorter `log --oneline`

```bash
git config --global alias.ll 'log --oneline'
```

Usage:

```bash
git ll
```

> [!tip]  
> Aliases are especially useful for Git commands that you use frequently or commands with long options.

# View Global Git Configuration

To display all global Git configuration properties:

```bash
git config --global --list
```

The shorthand form is:

```bash
git config --global -l
```

## Show the Configuration File Location

To see where each configuration value originates:

```bash
git config --global --list --show-origin
```

This is useful when troubleshooting configuration issues.

---

# Remove Global Git Configuration

You can remove a global configuration property using `--unset`.

### Remove Username

```bash
git config --global --unset user.name
```

### Remove Email

```bash
git config --global --unset user.email
```

### Remove Excludes File

```bash
git config --global --unset core.excludesfile
```

## Remove All Values for a Property

If a property has been configured multiple times, use `--unset-all`:

```bash
git config --global --unset-all user.name
```

```bash
git config --global --unset-all user.email
```

```bash
git config --global --unset-all core.excludesfile
```

---

# Remove an Entire Configuration Section

You can remove an entire configuration section using `--remove-section`.

For example:

```bash
git config --global --remove-section user
```

Or:

```bash
git config --global --remove-section core
```

> [!warning]  
> Removing a section deletes all configuration values contained within that section. Use this carefully.

---

# Replace Existing Configuration Values

To replace all existing values for a property with a new value:

```bash
git config --global --replace-all user.name "Your New Name"
```

```bash
git config --global --replace-all user.email "your_new_email@example.com"
```

---

# Edit the Global Git Configuration File

The global Git configuration is stored in a text file, commonly:

```text
~/.gitconfig
```

You can open it directly using:

```bash
git config --global --edit
```

Git opens the configuration file in the configured Git editor.

A `.gitconfig` file may contain sections such as:

```ini
[user]
    name = Your Name
    email = your_email@example.com

[core]
    editor = vim

[init]
    defaultBranch = main

[alias]
    st = status
    co = checkout
    ll = log --oneline
```

Changes made to the configuration file are used by Git when subsequent Git commands read the configuration.

# Useful Global Configuration Commands

|Command|Purpose|
|---|---|
|`git config --global user.name "Name"`|Set global username|
|`git config --global user.email "email"`|Set global email|
|`git config --global core.editor "vim"`|Set default editor|
|`git config --global init.defaultBranch main`|Set default initial branch|
|`git config --global fetch.prune true`|Enable automatic pruning during fetch|
|`git config --global alias.st status`|Create a Git alias|
|`git config --global --list`|Display global configuration|
|`git config --global --list --show-origin`|Display configuration and its source|
|`git config --global --unset <key>`|Remove a configuration property|
|`git config --global --unset-all <key>`|Remove all values for a property|
|`git config --global --remove-section <section>`|Remove an entire configuration section|
|`git config --global --replace-all <key> <value>`|Replace all existing values|
|`git config --global --edit`|Edit the global configuration file|

---

# Key Takeaways

- **Global configuration** applies to all repositories for the current user.
- **Local configuration** applies only to the current repository.
- Local configuration overrides global configuration when both define the same property.
- Global configuration is commonly stored in `~/.gitconfig`.
- Local configuration is stored in `.git/config`.
- `user.name` and `user.email` define the identity used for commits.
- `init.defaultBranch` can define the initial branch name for new repositories.
- Git aliases provide shortcuts for frequently used commands.
- `git config --global --list` displays global configuration.
- `git config --global --edit` opens the global configuration file for editing.
