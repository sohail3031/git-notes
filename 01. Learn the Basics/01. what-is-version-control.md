# What Is Version Control?

Version control, also known as **source control**, is the practice of tracking and managing changes to software code.

A **Version Control System (VCS)** is a software tool that helps software teams manage changes to source code over time. As development environments have accelerated, version control systems help teams work faster and more efficiently.

Version control is especially useful for **DevOps** teams because it helps reduce development time and increase the number of successful deployments.

## How Version Control Works

Version control software keeps track of every modification made to code in a special type of database.

If a mistake is made, developers can:

- Return to an earlier version of the code.
- Compare different versions of the code.
- Identify when and why a change was introduced.
- Fix mistakes while minimizing disruption to other team members.

For almost all software projects, the source code is a valuable asset whose value must be protected. For most software teams, source code contains the knowledge and understanding of the problem domain that developers have collected and refined over time.

Version control protects source code from:

- Data loss or other catastrophic failures.
- Accidental changes.
- Human errors.
- Unintended consequences of code changes.

## Version Control in Team Development

Software developers working in teams are continually:

- Writing new source code.
- Modifying existing source code.
- Fixing bugs.
- Developing new features.

The code for a project, application, or software component is typically organized into a folder structure, also known as a **file tree**.

For example, one developer might be working on a new feature while another developer fixes an unrelated bug. Both developers may make changes to different parts of the same file tree.

Version control helps teams manage this type of concurrent work by:

- Tracking individual changes made by each contributor.
- Maintaining a history of changes.
- Helping prevent conflicting changes.
- Allowing developers to work on different tasks simultaneously.

### Conflicting Changes

Changes made by one developer can sometimes be incompatible with changes made by another developer working at the same time.

Version control helps identify and resolve these conflicts in an orderly manner without unnecessarily blocking the work of other team members.

In addition, any software change can potentially introduce new bugs. New or modified software should therefore be tested before it can be considered reliable.

As a result, **development and testing proceed together** until a new version of the software is ready.

## Characteristics of Good Version Control Software

Good version control software should support a developer's preferred workflow without forcing everyone to follow one particular way of working.

Ideally, it should also:

- Work across different platforms.
- Avoid dictating which operating system developers must use.
- Support different development toolchains.
- Allow multiple developers to work concurrently.
- Facilitate a smooth and continuous flow of changes.

This is preferable to traditional **file locking**, where one developer is given permission to modify a file while other developers are blocked from working on it.

## Problems Without Version Control

Software teams that do not use version control can encounter several problems, such as:

- Not knowing which changes are currently available to users.
- Creating incompatible changes between different pieces of work.
- Having to manually untangle conflicting changes.
- Losing previous versions of files.
- Accidentally deleting useful code.

Developers who have never used version control may have encountered situations such as creating multiple versions of the same file:

```text
project-final
project-final-v2
project-final-latest
project-final-latest-new
```

Another common practice is commenting out code instead of deleting it because the developer may want to use the code again later.

Version control provides a structured solution to these problems by maintaining the history of changes without requiring developers to manually maintain multiple copies of files.

## Version Control for Individual Developers

Version control is not only useful for large software teams.

Individual developers can also benefit from version control when working on small or personal projects. Once developers become accustomed to the benefits of a capable version control system, it can become an essential part of their everyday development workflow.

Version control can even be useful for projects that are not strictly software-related.

# Benefits of Version Control Systems

Using version control software is considered a best practice for high-performing software and DevOps teams.

Version control helps developers work faster while allowing teams to maintain efficiency and agility as they grow.

**Version Control Systems (VCS)** have improved significantly over the past few decades.

They may also be referred to as:

- **SCM** — Source Code Management
- **RCS** — Revision Control System

One of the most popular version control systems is **Git**.

Git is a **Distributed Version Control System (DVCS)**. Git is also free and open source.

Regardless of the terminology or the specific VCS being used, the primary benefits of version control include:

## 1. Complete Change History

A version control system maintains a long-term history of changes made to files.

This history can include:

- File creation.
- File deletion.
- Changes to file contents.
- The author of each change.
- The date of each change.
- Notes describing the purpose of each change.

Different version control systems may differ in how well they handle file renaming and moving.

A complete change history allows developers to:

- Return to previous versions.
- Investigate the root cause of bugs.
- Understand how and why code changed.
- Fix problems in older versions of software.

When software is actively being developed, almost any previous state of the software can be considered an "older version."

## 2. Branching and Merging

Version control allows multiple developers to work concurrently.

Even individual developers can benefit from working on independent streams of changes.

A **branch** allows developers to maintain separate streams of work while keeping those changes independent from other branches.

Later, the changes can be **merged** back together.

Branching and merging allow developers to:

- Work on features independently.
- Keep changes isolated.
- Develop multiple features simultaneously.
- Merge completed work together.
- Identify and resolve conflicts between different streams of work.

Many software teams use different branching strategies, such as:

- A branch for each feature.
- A branch for each release.
- A combination of feature and release branches.

Different teams can adopt different branching and merging workflows depending on their development process.

## 3. Traceability

**Traceability** is the ability to track changes made to software and understand their purpose.

Version control can connect changes to project management and bug-tracking systems such as **Jira**.

Developers can also add messages describing the purpose and intent of each change.

Traceability helps with:

- Root cause analysis.
- Debugging and investigation.
- Understanding why a change was made.
- Understanding the history of existing code.
- Working with legacy code.
- Estimating future development work.

Having an annotated history of the code can be particularly useful when developers are trying to understand **what the code does and why it was designed that way**.

This historical context can help developers make changes that remain consistent with the intended long-term design of the system.

## Version Control Is Essential for Professional Software Development

Although it is possible to develop software without version control, doing so introduces significant risks.

For professional software teams, version control provides important capabilities for:

- Protecting source code.
- Tracking changes.
- Collaborating with other developers.
- Managing different versions of software.
- Developing features independently.
- Investigating bugs.
- Maintaining a reliable history of the project.

Therefore, the important question is not whether to use version control, but **which version control system to use**.

There are many version control systems available, but this course focuses on **Git**.
